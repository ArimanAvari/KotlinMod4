## Теория (очень кратко)

### Корутины (Kotlin Coroutines)
- `launch` — «запустил и забыл», возвращает `Job`, можно отменять.
- `async/await` — параллельная работа с возвращаемым результатом (`Deferred`).
- `withContext(Dispatchers.IO/Default/Main)` — переключение потока под задачу.
- Отмена через `Job.cancel()` / `scope.cancel()`, общий таймаут — `withTimeoutOrNull(...)`.
- Структурированный параллелизм: падение дочерней корутины может отменить всю иерархию (если не использовать обработку/`supervisorScope`).

### Services
- Service — компонент для длительной работы без UI.
- **Started service** (через `startService`) живёт до `stopSelf()/stopService`.
- **Bound service** (через `bindService`) живёт, пока есть привязанные клиенты.
- **Foreground service** — обязан показывать постоянное уведомление.

### WorkManager + Notifications
- WorkManager — надёжное выполнение фоновой работы с ограничениями и очередью.
- `OneTimeWorkRequest` — разовая, `PeriodicWorkRequest` — периодическая (мин. 15 мин).
- Цепочки: `beginWith(...).then(...).enqueue()`; уникальная цепочка: `beginUniqueWork(...)`.
- Уведомления: нужны **каналы** (Android 8+) и разрешение `POST_NOTIFICATIONS` (Android 13+).
- Долгие задачи с уведомлением: Foreground Service или `setForegroundAsync` в Worker (WorkManager 2.8+).

### Геолокация
- Основной API: `FusedLocationProviderClient`.
- Разрешения: `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION`.
- Обратное геокодирование: `Geocoder` (или альтернативы при ошибках/без интернета).

### AlarmManager + BroadcastReceiver
- AlarmManager — точные напоминания по времени.
- BroadcastReceiver — реакция на события (например, `BOOT_COMPLETED`) и показ уведомления.
- После перезагрузки напоминания нужно восстанавливать.

### Flow
- Flow — поток значений во времени.
- **cold Flow** запускается заново при каждом `collect`.
- **StateFlow** — hot поток, хранит последнее значение (идеален для состояния UI).
- В Compose: `collectAsStateWithLifecycle()` / `LaunchedEffect { collect { ... } }`.

### Сенсоры
- Доступ через `SensorManager`, подписка `registerListener`, отписка `unregisterListener`.
- Для экономии батареи: включать в `onResume`, выключать в `onPause`.
- Компас обычно строят на данных ориентации/магнитометра (азимут 0–360°).

### Задание 3: Экран поиска репозиториев GitHub с debounce

Debounce — это когда мы говорим функции: «Не выполняйся сразу. Подожди, пока меня перестанут дёргать хотя бы N миллисекунд. Тогда выполнись один раз с самыми свежими данными».  Дополнительно можно почитать тут: https://kotlincoroutines.ru/2025/12/25/%D1%83%D0%BF%D1%80%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5-%D0%BF%D0%BE%D1%82%D0%BE%D0%BA%D0%BE%D0%BC-%D0%B2-kotlin-flow/
	Самая простая реализация выглядит так: 

import kotlinx.coroutines.*

fun <T> CoroutineScope.debounce(
    waitMs: Long = 500L, destinationFunction: (T) -> Unit): (T) -> Unit {

    var debounceJob: Job? = null

    return { param: T ->

        debounceJob?.cancel()

        debounceJob = launch {

            delay(waitMs)

            destinationFunction(param)

        }
      }

}

Необходимо создать Android приложение. 
Требования к UI:

есть поле ввода;

при вводе текста происходит «поиск» репозиториев;

результаты отображаются в LazyColumn;

поиск запускается не на каждый символ, а с задержкой (debounce);

во время поиска показывается индикатор загрузки;

предыдущий поиск автоматически отменяется, если пользователь продолжает печатать;

Требования к корутинам:

Использовать launch/async/withContext/delay;

Реализовать debounce (можно с помощью delay + cancel);

Отмена предыдущей задачи при новом вводе текста (через Job.cancel())

Всё должно работать внутри rememberCoroutineScope()

Источник данных -  большой json-файл github_repos.json в assets или res/raw (можно взять ~50–200 записей репозиториев с полями: id, full_name, description, stargazers_count, language)

### Задание 14: Компас 

Функционал приложения:

Приложение показывает направление на магнитный север с помощью встроенных сенсоров смартфона. Основные возможности:

Отображение азимута

Показывает текущий азимут (угол от магнитного севера) в градусах (0° — север, 90° — восток, 180° — юг, 270° — запад);

Значение обновляется в реальном времени при повороте устройства.

Анимированная стрелка компаса 

Стрелка плавно поворачивается в сторону севера;

Красная часть стрелки указывает на север, серая— на юг;

Поворот анимирован (без резких скачков).

Автоматическое управление сенсорами

Слушатель включается, когда экран виден (onResume);

Слушатель выключается, когда экран не виден (onPause) — экономия батареи;

При отсутствии нужного сенсора — показывается сообщение об ошибке.

Сохранение поведения при повороте экрана

Стрелка и значения не «сбрасываются» при изменении ориентации устройства.

Требования к UI:

UI должен быть минималистичным, стильным и удобным для использования в тёмное время суток.

Центральный элемент — компас

Круглый диск диаметром ~70–80% ширины экрана;

Стрелка компаса (двухцветная: красная на север, чёрная на юг);

Стрелка занимает ~80% диаметра круга;

Над стрелкой — крупная буква «N»;

Текстовая информация

Вверху экрана — заголовок «Компас» 

Под стрелкой — крупный текст азимута: «Азимут: 142°»;

Сообщение об ошибке (если сенсор отсутствует)

Большой красный текст посередине: «Устройство не поддерживает датчик ориентации».
