## Что сделано в задании 3

Сделан экран поиска репозиториев GitHub на Jetpack Compose.

Что есть на экране:
- поле ввода;
- индикатор загрузки;
- список результатов в `LazyColumn`;
- debounce на ввод;
- отмена предыдущего поиска при новом вводе текста.

Источник данных лежит в `assets/github_repos.json`.

## Почему здесь именно Compose

В условии задания явно требовались:
- `LazyColumn`
- `rememberCoroutineScope()`

Поэтому экран был сделан не на XML, а на Compose.

## Как работает debounce

Есть расширение:

`CoroutineScope.debounce(waitMs, destinationFunction)`

Внутри него хранится `debounceJob`.

Когда пользователь вводит новый символ:
1. предыдущий `debounceJob` отменяется;
2. запускается новый `launch`;
3. внутри идёт `delay(500)`;
4. если за это время новых символов не было, запускается реальный поиск.

Это и есть debounce: не искать на каждый символ мгновенно, а подождать небольшую паузу.

## Как отменяется предыдущий поиск

Кроме `debounceJob`, есть ещё `searchJob`.

Когда debounce срабатывает на новый запрос:

`searchJob?.cancel()`

После этого запускается новый `searchJob`.

То есть если пользователь продолжает печатать, старый поиск уже не нужен и он отменяется.

## Где используются корутины

В задании просили использовать:
- `launch`
- `async`
- `withContext`
- `delay`

Все они здесь есть:

1. `launch`
Используется для debounce и для запуска самого поиска.

2. `async`
Используется для загрузки списка репозиториев из `assets`.

3. `withContext(Dispatchers.Default)`
Используется для фильтрации списка не на главном потоке.

4. `delay`
Используется в debounce и дополнительно для имитации небольшой загрузки, чтобы индикатор был виден.

## Как устроен поиск

Поиск проходит по трём полям:
- `full_name`
- `description`
- `language`

Сначала строка запроса приводится к нижнему регистру.
Потом каждый репозиторий проверяется на совпадение по этим полям.

Результаты потом сортируются по количеству звёзд `stargazers_count` по убыванию.

## Как загружаются данные

В `GithubRepository` читается `github_repos.json` из `assets`.

JSON парсится через `JSONArray`.

Для каждого элемента создаётся объект `GithubRepo`.

Дальше список кэшируется в `cachedRepos`, чтобы не читать файл заново при каждом новом запросе.
