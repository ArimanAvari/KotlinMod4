## Что сделано в задании 2

В этом задании сделан поиск дубликатов `json`-файлов по SHA-256 с параллельной обработкой, общим таймаутом и ручной отменой.

Я специально оформил экран так, чтобы он был похож на демонстрационный скрин:
- сверху крупный заголовок;
- ниже путь к тестовой директории;
- поле для ввода таймаута в секундах;
- кнопка запуска;
- отдельная большая серая область, куда построчно выводится весь ход поиска.

За счёт этого на защите можно просто нажать кнопку и показать весь процесс прямо на экране, без объяснения "где тут результат и что происходит".

## Как устроен экран

Экран описан в `activity_main.xml`.

На нём есть:
- `pathText` — показывает путь к папке, где идёт поиск;
- `timeoutInput` — поле, куда вводится таймаут;
- `startSearchButton` — запускает поиск;
- `cancelButton` — останавливает уже запущенный поиск;
- `outputText` — большая текстовая область для лога и результата.

Для `outputText` я поставил моноширинный шрифт и серый фон с закруглением, чтобы вывод визуально напоминал консольный отчёт, как на скриншоте.

## Почему создаётся тестовая папка

В `prepareDemoDirectory()` программа сама создаёт папку:

`filesDir/search_test`

И внутри готовит структуру:
- `file_a.json`
- `extra.json`
- `sub1/file_b.json`
- `sub1/file_c.json`
- `sub2/file_d.json`
- `file_e.json`
- `notes.txt`

Это нужно для двух вещей:

1. Приложение можно сразу запускать на телефоне или эмуляторе без ручной подготовки файлов.
2. На защите гарантированно будут одинаковые дубликаты, и результат всегда воспроизводится.

## Какие тут дубликаты

Сделаны две группы дубликатов:

1. Первая группа:
- `file_a.json`
- `extra.json`
- `sub1/file_b.json`

У них полностью одинаковое содержимое, значит и SHA-256 будет одинаковый.

2. Вторая группа:
- `sub1/file_c.json`
- `sub2/file_d.json`

У них тоже одинаковое содержимое и одинаковый хэш.

Файл `file_e.json` уникальный, поэтому в список дубликатов не попадёт.

Файл `notes.txt` нужен, чтобы показать, что поиск идёт только по `json`.

## Как запускается поиск

Когда пользователь нажимает кнопку `Найти дубликаты`, вызывается `runDuplicateSearch()`.

Там происходит такой сценарий:

1. Если старый поиск ещё идёт, он отменяется.
2. Очищается текстовая область вывода.
3. В лог добавляются первые строки:
- `Сканируем директорию...`
- `Таймаут: N сек`
4. Запускается корутина на главном потоке.
5. Внутри неё весь поиск оборачивается в `withTimeoutOrNull(...)`.

Если поиск успел завершиться вовремя, на экран выводится полный отчёт.
Если нет, программа пишет, что операция остановлена по таймауту.

## Как ищутся файлы

В `findDuplicateGroups()` используется:

`rootDir.walkTopDown()`

Это рекурсивный обход папки и всех вложенных подпапок.

Дальше фильтруются только те элементы, которые:
- являются файлами;
- имеют расширение `json`.

После этого на экран выводится строка:

`Найдено файлов: 6`

## Как сделана параллельность

После того как список `json`-файлов найден, для каждого файла создаётся отдельная корутина через:

`async(Dispatchers.IO)`

То есть хэш каждого файла считается параллельно, а не по одному в цикле.

Перед вычислением хэша для каждого файла в лог добавляется строка вида:

`Хэшируем: file_b.json`

Когда все задачи созданы, вызывается `awaitAll()`, и программа дожидается завершения всех вычислений.

Именно это и есть главный смысл задания: показать, что обработка нескольких файлов может идти одновременно.

## Как считается SHA-256

Для каждого файла вызывается `computeSha256(file)`.

Внутри функции:

1. Делается `delay(900)` — это искусственная задержка.
2. Создаётся объект `MessageDigest` для алгоритма `SHA-256`.
3. Файл читается как поток байтов.
4. Блоки байтов постепенно добавляются в digest.
5. В конце digest преобразуется в hex-строку.

Искусственная задержка нужна не просто так:
- она делает работу заметной визуально;
- позволяет показать таймаут;
- даёт время для ручной отмены.

## Как определяются дубликаты

После завершения хэширования получается набор пар:

`файл -> hash`

Дальше этот список группируется по самому хэшу.

Если у одного и того же хэша больше одного файла, значит это дубликаты.

Результат сохраняется в `DuplicateGroup`, где есть:
- сам хэш;
- список файлов из этой группы.

На экран это выводится так:

`=== Найдены дубликаты ===`

Потом для каждой группы:
- строка с короткой версией хэша;
- список файлов;
- в скобках указывается папка, где лежит файл.

Например:

`📄 file_b.json (sub1)`

Если файл лежит прямо в корневой тестовой папке, в скобках будет имя этой корневой папки:

`📄 extra.json (search_test)`

## Как работает таймаут

Весь поиск находится внутри:

`withTimeoutOrNull(timeoutSeconds * 1000)`

Если время вышло раньше, чем завершился поиск, `withTimeoutOrNull` возвращает `null`.

Тогда программа выводит:
- что поиск остановлен по таймауту;
- сколько миллисекунд реально прошло.

Это удобно для защиты, потому что можно показать не только успешный сценарий, но и ограничение по времени.

## Как работает ручная отмена

Текущая задача поиска хранится в `searchJob`.

Пока поиск идёт:
- кнопка запуска блокируется;
- поле таймаута тоже блокируется;
- появляется кнопка `Остановить`.

Если нажать `Остановить`, вызывается:

`searchJob?.cancel(...)`

После этого корутины корректно завершаются через `CancellationException`, а в лог выводится:

`Поиск остановлен вручную`

То есть приложение не падает и не зависает.

## Что говорить на защите

Коротко можно объяснить так:

1. Программа рекурсивно ищет все `json` в директории и подпапках.
2. Для каждого файла параллельно считается SHA-256 через `async(Dispatchers.IO)`.
3. Дубликаты определяются по одинаковому хэшу.
4. Весь поиск ограничен общим таймаутом через `withTimeoutOrNull`.
5. Есть ручная отмена через `Job.cancel()`.
6. Ход работы и итог выводятся прямо на экран в виде понятного текстового лога.
