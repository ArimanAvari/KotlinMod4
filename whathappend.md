## Что сделано в задании 1

Реализована первая задача из `task.md`: параллельная загрузка и обработка трёх независимых источников данных с задержками, замером общего времени и обработкой случайных сбоев.

Файлы данных добавлены в `app/src/main/assets`:
- `users.json`
- `sales.json`
- `weather.json`

Основная логика находится в `MainActivity.kt`.

## Принцип работы по шагам

1. При старте `Activity` вызывается `runTaskOne()`.
2. В `runTaskOne()` запускается корутина на главном потоке (`screenScope.launch`), чтобы:
   - показать стартовый текст,
   - измерить время выполнения через `measureTimeMillis`,
   - после завершения вывести общий отчёт.
3. Внутри `processSources()` используется `supervisorScope` и три `async(Dispatchers.IO)`:
   - `loadUsers()` с задержкой 1800 мс,
   - `loadSalesByProduct()` с задержкой 1200 мс,
   - `loadWeatherLines()` с задержкой 2500 мс.
4. Каждая задача обёрнута в `runCatching { ... }`, поэтому исключение не роняет всё приложение.
5. После `await()` собираются:
   - успешные результаты,
   - список ошибок с понятным текстом.
6. Формируется один итоговый отчёт: успешные данные + список ошибок (если есть).

## Почему выполняется примерно за 2.5 секунды

Задачи идут параллельно, а не последовательно.
Поэтому общее время определяется самой долгой задачей (погода, 2500 мс) + небольшой служебный оверхед.

Если бы задачи шли по очереди, было бы около 1800 + 1200 + 2500 = 5500 мс.

## Как сделан случайный сбой

Функция `maybeFail(sourceName: String)` вызывается внутри каждой загрузки.
С вероятностью 30% она кидает `IllegalStateException` с названием источника.

Это нужно, чтобы показать обработку ошибок в реальном сценарии, когда какой-то источник может быть недоступен.

## Почему приложение не падает

- `supervisorScope` не отменяет соседние задачи при падении одной.
- `runCatching` переводит исключение в `Result.Failure`.
- В итоге падение одной операции превращается в текст ошибки на экране, а не в краш.
