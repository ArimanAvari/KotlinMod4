## Что сделано в задании 8

Сделана последовательная цепочка обработки фото перед загрузкой в облако.

Шаги идут строго по порядку:
1. сжатие;
2. добавление водяного знака;
3. загрузка в облако.

Для этого использован `WorkManager` и цепочка из трёх `Worker`.

## Почему здесь WorkManager

В задании есть явная последовательная цепочка зависимых фоновых шагов.

`WorkManager` хорошо подходит, потому что умеет:
- строить цепочки `beginWith(...).then(...).then(...)`;
- передавать данные между шагами;
- наблюдать за прогрессом и финальным результатом.

## Какие worker-ы есть

1. `CompressPhotoWorker`
Имитирует сжатие фото и отдаёт имя файла `compressed_...`

2. `AddWatermarkWorker`
Берёт результат предыдущего шага, добавляет подпись и отдаёт `watermarked_...`

3. `UploadPhotoWorker`
Берёт готовый файл и имитирует загрузку в облако, в конце отдаёт путь `cloud/...`

## Как шаги связаны между собой

В `MainActivity` создаётся цепочка:

`compress -> watermark -> upload`

То есть второй шаг стартует только после успешного завершения первого.
Третий — только после второго.

Если любой шаг вернёт `Result.failure()`, вся цепочка дальше не пойдёт.

## Как передаются данные

Между worker-ами используется `Data`.

Через `Data` передаются:
- имя исходного файла;
- имя обработанного файла;
- путь результата;
- статус;
- прогресс;
- текст ошибки.

## Как показывается прогресс

В каждом worker есть несколько этапов с `setProgress(...)`.

Например, во время сжатия прогресс последовательно меняется:
- 10
- 30
- 50
- 70
- 100

Так же сделано и для остальных шагов.

UI наблюдает за `WorkInfo` последнего worker-а и получает оттуда:
- текущий статус;
- текущий процент.

Поэтому на экране можно видеть:
- `Сжимаем фото...`
- `Добавляем водяной знак...`
- `Загружаем фото в облако...`

## Что происходит в конце

Если всё прошло успешно:
- кнопка снова становится активной;
- на экране выводится `Готово! Фото загружено`;
- ниже показывается путь вида `cloud/watermarked_compressed_photo_001.jpg`

Если какой-то этап упадёт:
- UI получит `FAILED`;
- покажет текст ошибки;
- дальнейшая цепочка не пойдёт.

## Что говорить на защите

Коротко:

1. Для последовательной фоновой цепочки использован WorkManager.
2. Каждый шаг реализован отдельным Worker.
3. Данные между шагами передаются через `Data`.
4. Прогресс и статус приходят в Activity через `WorkInfo`.
5. Если любой шаг упадёт, WorkManager останавливает всю цепочку.
