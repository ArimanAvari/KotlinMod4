## Что сделано в задании 4

Сделана социальная лента на Jetpack Compose.

На старте экран:
- читает список постов из `social_posts.json`;
- для каждого поста отдельно и параллельно загружает аватарку и комментарии;
- обновляет карточки по мере готовности, а не ждёт завершения всей ленты.

Есть кнопка `Обновить`, которая отменяет все текущие загрузки и запускает всё заново.

## Почему здесь Compose

В условии есть прямое требование использовать `rememberCoroutineScope()`, поэтому экран логично сделан на Compose.

## Как устроена загрузка ленты

Главный экран хранит:
- список карточек `posts`;
- список активных `Job`;
- флаг `isRefreshing`.

Когда вызывается `refreshFeed()`:
1. отменяются все текущие `Job`;
2. очищается список старых карточек;
3. снова читаются посты из JSON;
4. для каждого поста стартует отдельная корутина загрузки.

## Как один пост загружается параллельно

Для каждого поста вызывается `launchPostLoading(...)`.

Внутри используется `supervisorScope`, а потом запускаются две подзадачи через `async`:
- загрузка аватарки;
- загрузка комментариев.

Дальше идёт `await()` у обеих задач.

Если обе успешны, карточка получает статус `Ready`.
Если хотя бы одна провалилась, карточка получает статус `Error`, но пост всё равно остаётся на экране.

Это важно: падение одной карточки не ломает всю ленту.

## Как имитируется сеть

В репозитории специально стоят задержки:
- `loadPosts()` -> `delay(500)`
- `loadAvatar()` -> `delay(650)`
- `loadComments()` -> `delay(900)`

Это нужно, чтобы визуально было видно:
- что карточки загружаются не мгновенно;
- что аватарки и комментарии приходят асинхронно;
- что обновление реально отменяет старые задачи.

## Как сделаны ошибки

Чтобы показать состояние `Error`, некоторые загрузки специально падают:
- аватарка падает у постов `4` и `9`;
- комментарии падают у постов `6` и `11`.

Из-за этого можно на защите показать все состояния карточек:
- `Loading`
- `Ready`
- `Error`

## Что показывается в UI

В каждой карточке есть:
- аватарка или placeholder `ERR`;
- заголовок поста;
- текст поста;
- статус загрузки;
- блок комментариев.

Если комментарии не загрузились, показывается текст:

`Не удалось загрузить комментарии`

Если аватарка не загрузилась, вместо неё рисуется серый круг с `ERR`.

## Что говорить на защите

Короткий вариант:

1. Посты читаются из локального JSON.
2. Для каждого поста параллельно запускаются две корутины: аватарка и комментарии.
3. Используется `rememberCoroutineScope()` для запуска задач из composable.
4. Используется `supervisorScope`, чтобы ошибка внутри одной подзадачи не ломала вторую.
5. Кнопка `Обновить` делает `Job.cancel()` для всех активных задач и запускает новую загрузку.
6. Поэтому лента постепенно оживает по карточкам и хорошо показывает работу корутин.
