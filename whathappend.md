## Что сделано в задании 9

Сделана параллельная загрузка погоды для нескольких городов с финальной сборкой отчёта.

Используется `WorkManager`:
- три worker-а параллельно грузят погоду по городам;
- финальный worker собирает итоговый отчёт;
- уведомление обновляется по ходу выполнения.

## Какие шаги есть в решении

1. Пользователь нажимает кнопку `Собрать прогноз`.
2. Создаются три параллельных `LoadWeatherWorker`:
- Москва
- Лондон
- Нью-Йорк
3. После их завершения запускается `BuildWeatherReportWorker`.
4. Он считает среднюю температуру и формирует итоговый текст.

## Почему здесь WorkManager

В условии прямо предложено использовать `WorkManager` с `setForegroundAsync` / foreground-логикой внутри worker-ов.

Это удобно, потому что:
- работа может жить долго;
- есть параллельные шаги;
- есть финальный зависимый шаг;
- можно обновлять уведомление и отслеживать прогресс.

## Как сделана параллельность

Три `LoadWeatherWorker` создаются отдельно.

Они запускаются одновременно и каждый:
- ждёт свой `delay`;
- имитирует получение температуры;
- сохраняет результат в `Data`.

Это даёт реальную параллельную обработку, а не последовательную.

## Как обновляется уведомление

Есть `WeatherNotificationHelper`.

Он:
- создаёт notification channel;
- показывает стартовое ongoing-уведомление;
- обновляет текст по мере завершения городов;
- показывает финальное уведомление с итоговой средней температурой.

Чтобы worker-ы знали, кто уже завершился, используется `WeatherProgressStore`.

Он хранит:
- список всех городов;
- список уже завершённых городов.

Когда очередной worker заканчивает работу, уведомление меняется примерно так:
- `Загружаем погоду для 3 городов...`
- `Готово: Москва, Лондон, Нью-Йорк в процессе...`
- `Все данные получены, формируем отчёт...`
- `Отчёт готов! Средняя температура +6°C`

## Как финальный worker получает данные

Для `BuildWeatherReportWorker` используется `ArrayCreatingInputMerger`.

Это нужно, чтобы собрать выходные данные всех предыдущих worker-ов в один общий вход финального worker-а.

В результате финальный шаг получает:
- массив городов;
- массив температур.

После этого считает среднее значение и формирует отчёт.

## Что показывает UI

На экране есть:
- статус текущего шага;
- progress bar;
- кнопка запуска;
- итоговый текст отчёта или ошибка.

UI наблюдает за `WorkInfo` последнего worker-а и по нему обновляет экран.

## Что говорить на защите

Коротко:

1. Несколько worker-ов параллельно получают погоду по городам.
2. Каждый worker обновляет foreground-уведомление.
3. После завершения всех worker-ов запускается финальный шаг.
4. Финальный worker считает среднюю температуру и формирует итоговый отчёт.
5. Поэтому здесь есть и параллельная обработка, и итоговая сборка результата.
